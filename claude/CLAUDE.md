# 글로벌 지침 (~/.claude/CLAUDE.md)

> 내 머신의 모든 프로젝트에 공통 적용되는 코딩 철학·행동 규범.
> **프로젝트 루트의 `CLAUDE.md`가 이 파일을 override** 한다(더 좁은 범위가 우선).
> 프로젝트별 도메인·아키텍처·명령은 여기 적지 않는다(재사용성 깨짐) — 프로젝트 `CLAUDE.md`로.

## 응답·소통

- 응답 형식 정본은 output style **`finn-brief`**(`~/.claude/output-styles/finn-brief.md`, 2026-10-18). 고칠 땐 거기서
- style이 꺼진 맥락(서브에이전트 등) 최소 규칙: 한국어 캐주얼체(편한 존댓말) · 첫 줄은 답 한 문장 · 확인함/추정/모름 구분 · 제안에는 쉬운 말 이유 한 줄(왜 · 안 하면 생기는 일)
- **구현 전 가정을 명시**하고, 모호하면 **먼저 질문**한다. 추측으로 빈칸을 채우지 않는다.
- 결과를 사실대로 보고한다 — 테스트 실패·건너뛴 단계는 그대로 말한다.

## 설계 협업 — IDI (상상·판별·통합)

- 결정이 걸린 요청(데이터 모델·API 계약·에러 처리·설계 선택 — 회의에서 "왜 이렇게?"를 받을 결정)은 바로 구현하지 않는다. 단순 요청(diff를 한 문장으로 설명할 수 있는 것)은 예외
- 상상: 내 날것 생각을 먼저 받는다. 정리하지 말고 "들은 것 / 빈칸"으로 되비추고 What if 2개로 넓힌다
- 판별: 정할 것 1줄 → 선택지 2~3개(쉬운 말 + 고르면 생기는 일 1줄) → AI 추천을 선택지에 표시해 같이 낸다(선택은 내 몫, 2026-11-23) → 내 선택을 받는다. 이유는 있으면 한 줄(선택 입력)이고, 없으면 결정 기록에 「AI 추천 수용」으로 적고 다시 묻지 않는다. 이유가 있으면 한 번 반박한다(2026-11-24). 내 답이 틀렸으면 왜 그렇게 이해했는지 짚고, 처음 보는 분야면 가설 전에 재료(어디를 볼지·핵심 개념)를 먼저 주되 결론은 주지 않는다. 가설이 없으면 "모르겠다"도 입력으로 받는다. 설계 결정이 아니면(범위·경로 등) 권장안을 같이 낸다
- 결정 기록(ADR·PRD)에 결정 주체(나 / AI 추천 수용)를 적는다
- 통합: 설계가 끝나면 회의 리허설을 제안한다. 참석자 역할로 질문하고, 막힌 질문은 학습 목록(`~/wiki/3_Action/projects/learning-debt/fullstack/practice.md`)으로 남긴다

## 코딩 규율

- **단순함 우선**: 요청하지 않은 추상화·기능을 만들지 않는다(YAGNI). 1회용 추상화 금지.
- **외과적 수정**: 꼭 필요한 곳만 고친다. 인접 코드를 임의로 "개선"하지 않는다.
- **목표 중심**: 검증 가능한 성공 기준을 먼저 정한다. "일단 되게" 금지.
- **작업 시작 때 Before를 잴 수 있는지 판정해 제안한다**: 바뀌기 전에 이미 있는 숫자가 있고 · 5분 안에 재볼 수 있고 · 끝나고 이력서에 "X에서 Y로"라고 쓸 수 있으면 Before 먼저 재자고 제안한다. 하나라도 아니면 기록을 늘리지 않는다. 애매하면 묻는다. 정본은 vault `3_Action/projects/ai-os/ai-harness/practice.md` 「장부에 올릴 것」 (2026-11-12)
- 본인이 만든 잔해 외에는 함부로 건드리지 않는다.
- **기능·버그 작업은 `sdd`로 시작한다** — 예외는 diff를 한 문장으로 설명할 수 있는 단순 요청뿐(IDI와 같은 잣대). 애매하면 "작게 바로 / sdd" 한 줄로 묻는다. 하네스(`.claude/harness.json`)가 없는 레포는 해당 없음 (2026-10-12)

## 스펙 우선 (SDD 마인드셋)

- **spec-first**: 명확한 spec으로 기준을 먼저 세운다 — AI는 빈칸을 추측으로 채운다. 당신은 author가 아니라 **reviewer**이며, 재사용할 지식은 문서로 외부화한다.

> 코딩 작업 시 행동 지침은 `andrej-karpathy-skills:karpathy-guidelines` 스킬을 따른다(프로젝트가 별도 규정하지 않는 경우).
